# Telegram-бот закладок

Отдельный polling worker, Python 3.13, стандартная библиотека. Публичный website API не вызывается. Рабочий каталог упаковывается в bookmarks.json из текущего site/links, включая теги и RU/EN описания. Поиск открыт всем пользователям в личном чате. Добавление и экспорт доступны только владельцу.

## Что работает

- Стартовое меню: «Найти закладки», «Материалы с воркшопа», «Уютный ТГ» (https://t.me/nikir_public).
- «Найти закладки» открывает реактивный HTML-виджет с поиском по всему опубликованному архиву. Запрос вводится обычным сообщением Telegram или выбирается быстрым чипом. Виджеты не поддерживают клавиатуру и текстовые input; кнопка запроса вызывает ForceReply в чате.
- Результаты и две карточки на странице обновляются через widget_query → answerWidgetQuery → editMessageWidgetData. Контекст пользователя и message_id сохраняются в SQLite; другой пользователь не может редактировать карточку. Пустое состояние и ошибки отображаются внутри виджета. Все состояния укладываются в 1024 байта.
- «Материалы с воркшопа» открывает два пункта: «Ссылки с презентации» (поисковый виджет с 66 точными ссылками из Figma-фрейма 5462:198) и «Интерфейс для работы с анимацией» (оригинальный Animation Player.zip). В поиске материалов три раздела; обычные текстовые запросы фильтруют текущую карточку. Внешние шрифты и изображения не подключаются: используются тема Telegram и структура Links.
- Если сервер не поддерживает sendWidget (400/404), показываются обычные кнопки со всеми ссылками и навигацией. Старый клиент может показывать unsupported media, поэтому под карточкой всегда есть обычная кнопка «Открыть в Figma».
- ZIP приложен к сервису без изменений (контрольная сумма archive.sha256). По кнопке отправляется документ с подписью «Интерфейс для работы с анимацией». Альтернатива загрузке из файла — WORKSHOP_ZIP_FILE_ID.
- События поступают отдельно через @Maonez_admin_bot в «Админку», тему закладок: запуск сервиса, /start, выбор меню, поисковый текст, действие в виджете, отправка виджета и успешная отправка архива. BOOKMARK_ADMIN_EVENTS=true включает SQLite-очередь с повторами; отдельные BOOKMARK_ADMIN_BOT_TOKEN, BOOKMARK_ADMIN_CHAT_ID, BOOKMARK_ADMIN_THREAD_ID задают маршрут. Ключи и содержимое файлов в события не попадают. Ошибка админ-канала не останавливает поиск.
- Внешние переходы по ссылкам не отправляют widget_query и не считаются посещениями сайтов. События выбора отражают меню, фильтры и страницы, а не подтверждённое открытие стороннего сайта.
- Обычный текст или /search запрос: публичный поиск по опубликованному каталогу. Владелец дополнительно ищет в своих подтверждённых импортах. Русские и английские слова, несколько предметных синонимов (оплата, шрифты, анимация). Это словарный поиск, не универсальный семантический AI. Лимит 15 поисков за минуту на пользователя.
- Только владелец: фото или JPG/PNG документ до 8 МБ. Vision-модель извлекает видимые URL, заметки RU/EN и теги. Обрезанные адреса не достраиваются по догадке. Файлы обычных пользователей не скачиваются и не передаются модели.
- Предпросмотр всех записей, затем кнопки «Сохранить» / «Отмена». Сохранение идемпотентное, URL без www и завершающего слеша считаются одним сайтом.
- Сохранённые ссылки сразу доступны поиску в боте. SQLite, курсор Telegram и подтверждения сохраняются на постоянном диске.
- /export присылает JSON-файл с подтверждёнными импортами.
- В общий сайт ничего не публикуется автоматически. export_manifest.py выводит манифест, совместимый с scripts/prepare_screenshot_catalog.py.

## Подключение

1. Создать отдельный Railway service из services/bookmark-bot в репозитории mosolov-work. Существующий bookmark-api не менять.
2. Подключить persistent volume в /data и задать BOT_STATE_DIR=/data (либо использовать RAILWAY_VOLUME_MOUNT_PATH).
3. Задать BOOKMARK_BOT_TOKEN через секреты сервиса. Не использовать токен чужого продукта или бота уведомлений без выбора владельца.
4. Задать BOOKMARK_BOT_OWNER_ID: числовой Telegram user ID владельца. Он имеет доступ к добавлению и экспорту. Для совместимости поддержан прежний BOOKMARK_BOT_ALLOWED_USERS как список владельцев, только если новый параметр не задан. Для текущего сценария указать только один ID. Имя пользователя не используется для авторизации. В группах бот не отвечает.
5. Для скриншотов задать BOT_VISION_BASE_URL (HTTPS API с /chat/completions), BOT_VISION_API_KEY, BOT_VISION_MODEL. Требуется модель с поддержкой image_url. Текстовый DeepSeek для этой задачи не подходит. Без vision-конфигурации поиск работает, загрузка сообщает, что ещё не подключена.
6. Убедиться, что у выбранного бота нет активного webhook; polling и webhook несовместимы. Отключать webhook только у выбранного пользователем бота. Один worker, одна реплика.
7. Запустить worker и вручную отправить /start, запрос и скриншот. При подготовке live Telegram и модель не вызываются, сообщения не отправляются.

## Проверка и обновление каталога

```sh
python3 -m unittest discover -s bot -p 'test_*.py'
node bot/test_widget.cjs
node bot/test_search_widget.cjs
cp deploy/catalog-source/site/links/bookmarks.json bot/bookmarks.json
python3 bot/export_manifest.py /path/to/bookmark-bot.sqlite3 > /tmp/bot-import.json
```

Экспорт требуется просмотреть перед публикацией, особенно распознанные адреса: OCR может ошибаться. Файл можно передать существующему prepare_screenshot_catalog.py вторым аргументом. Перед применением сделать копию манифеста в data/; выполнить targets curated, reviews, english-local, english-release, published; затем обновить кэш переводов и запустить обычный workflow Pages.

## Ограничения и эксплуатация

20 vision-запросов на пользователя за UTC-сутки; не более 20 ссылок со скриншота. Черновик действует сутки. Изображения не сохраняются в SQLite. Логи содержат только update_id и общую категорию ошибки, без текстов, токенов и адресов Telegram-файлов.

URL со скрина не загружаются сервером. Заблокированный bookmark-search API исключён из импорта и поиска. Бот не имеет GitHub-токена и не может сам изменить сайт. Повторная доставка update после аварийного завершения может повторить ответ или распознавание; подтверждённый импорт при этом не дублируется. Ошибочный update подтверждается после короткого сообщения об ошибке; пользователь может прислать скрин заново.

Локальные тесты используют фальшивый Telegram и vision. Для production ещё нужны выбранный бот, его секрет, ID владельца, vision-провайдер и подключение постоянного диска. Не считать сервис запущенным до этих действий.
